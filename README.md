# gdebenz_server

Потенциально совместимый авторитетный WebSocket-сервер для игры
[`citi_ads`](https://github.com/Evsikoff/citi_ads). Исходники клиента не изменяются.

Сервер:

- принимает имя, управление или координаты игрока и взаимодействия с объектами;
- генерирует детерминированную карту в формате клиентского `City`;
- симулирует физику игроков, расход топлива и движение ботов;
- передаёт позиции игроков и ботов всем клиентам;
- управляет АЗС, рекламными щитами, канистрами и единственной базой;
- уменьшает число ботов на одного при каждом подключении игрока;
- перестраивает карту при росте или уменьшении числа игроков и добавляет ранее подключённым игрокам до 10 л топлива.

## Запуск

Нужен Node.js 22 или новее.

```bash
npm install
npm run dev
```

По умолчанию:

- WebSocket: `ws://localhost:8080/ws`
- проверка состояния: `http://localhost:8080/health`
- краткая информация о протоколе: `http://localhost:8080/protocol`

Для production:

```bash
npm run build
npm start
```

Переменные окружения перечислены в `.env.example`: `HOST`, `PORT` и список
разрешённых origin через запятую в `ALLOWED_ORIGINS`. Значение `*` разрешает
подключение с любого origin.

Docker:

```bash
docker build -t gdebenz-server .
docker run --rm -p 8080:8080 gdebenz-server
```

## Игровые настройки

Все числа находятся в [`src/config.ts`](src/config.ts). Файл повторяет настройки
клиента (`botCount`, расход топлива, таймауты, стартовые ресурсы, цены и лимиты
АЗС) и добавляет серверные частоты, параметры карты и ограничения протокола.

Правило количества ботов:

```text
bots = max(0, CONFIG.botCount - connectedPlayers)
```

Правило масштаба карты реализовано буквально по требованиям:

```text
ratio = connectedPlayers / CONFIG.botCount
scale = ratio > 2 ? floor(ratio) : 1
```

`scale` увеличивает обе стороны карты. Поэтому площадь, число АЗС, канистр и
рекламных щитов растут в `scale²` раз и объекты равномерно распределяются по
новой площади. База во всех случаях одна.

При любом изменении `scale` сервер:

1. увеличивает `worldRevision` и генерирует новую карту;
2. рассылает `world:map-update` уже подключённым игрокам;
3. добавляет каждому из них `min(10, tankVolume - fuel)` литров;
4. ограничивает координаты новыми границами и пересоздаёт нужное число ботов.

Новый игрок, вызвавший изменение размера, бонус не получает: он сразу начинает
со стартовым баком из конфигурации.

## WebSocket-протокол v1

Каждое сообщение — JSON-объект:

```json
{
  "type": "player:join",
  "payload": { "name": "Ева" }
}
```

Сразу после соединения сервер отправляет `server:hello`. До присоединения клиент
может отправлять только `player:join` и `ping`.

### Сообщения клиента

#### `player:join`

```json
{ "type": "player:join", "payload": { "name": "Ева" } }
```

В ответ приходят `player:welcome` и полный `world:snapshot`.

#### `player:input` — рекомендуемый авторитетный режим

```json
{
  "type": "player:input",
  "payload": {
    "seq": 14,
    "worldRevision": 1,
    "up": true,
    "down": false,
    "left": false,
    "right": true,
    "handbrake": false
  }
}
```

`seq` должен монотонно увеличиваться. Сервер применяет те же базовые значения
разгона, торможения, максимальной скорости и поворотливости, что и клиент.

#### `player:move` — режим совместимости с текущей локальной физикой

```json
{
  "type": "player:move",
  "payload": {
    "seq": 15,
    "worldRevision": 1,
    "x": 5235,
    "y": 6400,
    "angle": -1.57,
    "speed": 310
  }
}
```

Сервер проверяет последовательность, ревизию мира, границы и физически возможное
расстояние между обновлениями. Этот режим позволяет сначала подключить текущий
`CityRideGame`, а позже перенести физику целиком на сервер без смены остальных
сообщений.

#### `world:interact`

```json
{
  "type": "world:interact",
  "payload": {
    "requestId": "action-42",
    "objectType": "station",
    "objectId": "station:4:7",
    "amount": 12.5
  }
}
```

Поддерживаемые объекты:

| `objectType` | Действие | `amount` |
| --- | --- | --- |
| `canister` | подобрать канистру, увеличить бак на 10 л | не нужен |
| `billboard` | включить cooldown и открыть случайную АЗС | не нужен |
| `station` | купить бензин, заблокировать АЗС и запустить таймер | желаемые литры, необязательно |
| `base` | продать не более половины текущего топлива | литры, необязательно |

Перед действием сервер проверяет расстояние игрока до объекта и актуальное
состояние объекта. Ответ — `interaction:result` с тем же `requestId`.

#### `ping`

```json
{ "type": "ping", "payload": { "clientTime": 1756300000000 } }
```

Ответ: `pong` с `serverTime`.

### Сообщения сервера

- `server:hello` — версия протокола и частоты симуляции/снимков;
- `player:welcome` — id и начальное состояние своего игрока;
- `world:snapshot` — полная карта и все игровые сущности после входа;
- `world:entities` — частые позиции и ресурсы игроков, состояния ботов;
- `world:objects` — изменившиеся состояния АЗС, щитов и канистр;
- `world:map-update` — полная новая карта после изменения масштаба;
- `player:joined`, `player:left` — изменение состава комнаты;
- `interaction:result` — результат действия с объектом;
- `server:error` — отклонённое или неверное сообщение;
- `pong` — ответ на `ping`.

Координаты всех игроков и ботов в `world:entities` относятся к указанному там
`worldRevision`. Клиент не должен применять пакет от старой ревизии после
`world:map-update`.

## Формат карты

`world:snapshot.payload.map` и `world:map-update.payload.map` содержат структуру,
аналогичную `City` из клиента:

```text
blocks, parks, buildings, billboards, trees, lamps,
stations, base, canisters, roadCenters
```

Сервер добавляет каждому интерактивному или декоративному объекту стабильный
`id`, а также `meta`:

```json
{
  "revision": 1,
  "seed": 20260214,
  "scale": 1,
  "grid": 10,
  "worldSize": 10470,
  "blockSize": 860,
  "roadWidth": 170
}
```

Число `10470` следует непосредственно из формулы клиента:
`grid * blockSize + (grid + 1) * roadWidth`.

## Как подключить существующую игру позже

Текущая версия `citi_ads` полностью локальная и WebSocket пока не использует.
Минимальная будущая интеграция состоит из четырёх точек:

1. после меню открыть `/ws`, отправить `player:join` и заменить результат
   `buildCity(...)` картой из `world:snapshot`;
2. отправлять либо клавиши как `player:input`, либо состояние локальной машины
   как `player:move`;
3. вместо локального `createBots/stepBot` рисовать ботов и других игроков из
   `world:entities`;
4. направить подборы/заправку/щит/базу через `world:interact` и при
   `world:map-update` атомарно заменить `city`, фон мини-карты и `WORLD`.

Так сервер уже готов к совместной игре, но клиентский репозиторий остаётся без
изменений, как и требовалось.

## Проверки

```bash
npm run typecheck
npm test
npm run build
```

Тесты покрывают граничные значения формулы масштаба, пропорции карты,
детерминированную генерацию, уменьшение/восстановление числа ботов, топливный
бонус, игровые взаимодействия, проверку сообщений и настоящий WebSocket-handshake.
